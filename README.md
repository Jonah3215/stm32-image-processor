# STM32 Image Processor

C implementation of a real-time image signal processing (ISP) pipeline for Bayer RAW image data, designed for resource-constrained embedded systems such as STM32 microcontrollers. This implementation was  integrated into an embedded STM32-based digital camera. The project also includes desktop simulation tools for generating test images and visualizing the processed RGB565 output.

## Overview

The image processor takes a Bayer-pattern RAW image and processes it through a series of configurable ISP stages before producing RGB565 pixel data.

```text
Bayer RAW
    ↓
Line Buffer / Demosaicing
    ↓
Color Correction Matrix
    ↓
Hue / Saturation / Contrast
    ↓
Gamma Correction
    ↓
Night Mode / Banding / Monochrome
    ↓
RGB565 Output
```

The implementation processes the image one row at a time using a circular line buffer, allowing it to operate without storing the entire image in memory. This models the streaming processing approach used when receiving image data from a camera sensor through DMA.

## Processing Pipeline

### Bayer Demosaicing

The input image uses a **GRBG Bayer pattern**. The processor reconstructs RGB pixels from neighboring Bayer samples using a line-based demosaicing algorithm.

A three/four-row circular buffer is used to provide the neighboring pixels required for processing while avoiding a full-frame image buffer.

### Color Correction

A configurable **3×3 Color Correction Matrix (CCM)** transforms the demosaiced RGB values.

This can be used to compensate for sensor color characteristics and adjust the relationship between the color channels.

### Hue Rotation

Hue can be rotated using precomputed sine and cosine lookup tables. This allows the hue transformation to be performed efficiently without repeatedly calculating trigonometric functions during image processing.

### Saturation and Contrast

The processor supports configurable saturation and contrast adjustments after color correction.

### Gamma Correction

Gamma correction is implemented using lookup tables. Multiple gamma curves are available:

* Linear
* Gamma 1.8
* Gamma 2.2
* Gamma 2.6
* Gamma 3.0

Using lookup tables avoids performing expensive power operations for every pixel.

### Additional Processing

The processor also includes support for:
* Monochrome output
* Saturation and contrast adjustment

### RGB565 Output

The final RGB values are packed into **16-bit RGB565** format:

```text
RRRR RGGG GGGB BBBB
```

This format provides:

* 5 bits red
* 6 bits green
* 5 bits blue

The resulting data can be written directly to a display or other RGB565-compatible output.

## Desktop Simulation

The desktop implementation provides a convenient environment for developing and validating the image-processing algorithms before integrating them into an STM32 firmware environment.

The included Python utilities provide a simple test pipeline:

```text
pattern_generator.py
        ↓
  test_image.raw
        ↓
 image_processor.c
        ↓
simulated_display.raw
        ↓
 rgb565_to_png.py
        ↓
 final_result.png
```

### Test Pattern Generator

`pattern_generator.py` generates a synthetic 240×240 RGB test image containing:

* Color bars
* A grayscale gradient
* A low-light gradient

The RGB image is then encoded into a **GRBG Bayer pattern** and written as RAW bytes.

The different regions are intended to exercise different parts of the ISP:

| Test Pattern       | Processing                  |
| ------------------ | --------------------------- |
| Color bars         | Hue, saturation, monochrome |
| Grayscale gradient | Contrast, banding           |
| Low-light gradient | Night mode, banding         |

### RGB565 Visualizer

`rgb565_to_png.py` reads the RGB565 output generated by the C implementation, unpacks the 16-bit pixels into 8-bit RGB channels, and saves the result as a PNG for easy inspection.

## Running the Desktop Simulation

The test pipeline can be run in three stages.

### 1. Generate a Test Image

```bash
python pattern_generator.py
```

This generates:

```text
test_images/test_image.raw
```

### 2. Run the Image Processor

Compile and run `image_processor.c` using your preferred C compiler.

The desktop simulation reads:

```text
test_images/test_image.raw
```

and produces:

```text
test_images/simulated_display.raw
```

### 3. Convert the Output to PNG

```bash
python rgb565_to_png.py
```

This produces:

```text
test_images/final_result.png
```

The resulting PNG can then be opened to visually inspect the processed image.

## Embedded Design Considerations

The ISP was designed around constraints typical of embedded image processing:

* Streaming/line-based processing rather than full-frame buffering
* Fixed-size lookup tables for expensive mathematical operations
* Integer-based pixel processing where practical
* ARM-specific saturation instructions (`__USAT`) with a desktop-compatible implementation
* RGB565 output for memory and bandwidth-efficient display interfaces
* Processing structured around rows of image data suitable for DMA-driven input
